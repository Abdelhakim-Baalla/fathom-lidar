ESP32 Wi-Fi CSI Motion Sensing

Wi-Fi channel state information describes how a radio signal changes across subcarriers. Fathom visualizes those measurements and detects changes consistent with motion near a radio link.

What you need

Use an ESP32 running compatible Espressif esp-csi firmware. Ordinary browser access to a router does not expose CSI. The console cannot use a laptop Wi-Fi connection alone to reconstruct a room or scan through walls.

For a visual demonstration without a board, open Wi-Fi and select Simulation. It models a transmitter and receiver with direct and reflected paths. The people setting changes that model; it is not a measured people count.

Connect over USB

Open Fathom on HTTPS or localhost in a browser that supports Web Serial, such as desktop Chrome or Edge. Select Wi-Fi, choose USB ESP32, then select your board from the browser device picker. The serial reader expects compatible esp-csi output at 921600 baud.

If no measurements arrive, check the firmware, serial permissions and cable. A connected port alone does not mean CSI packets are arriving. The packets-per-second readout distinguishes an open connection from measured input.

Connect through the bridge

Alternatively, install the bridge CSI extra with uv sync --extra csi and run uv run fathom-bridge --csi-serial /dev/ttyUSB0. Replace the device path with your board’s serial port. Select Bridge in the Wi-Fi controls and enter its WebSocket address.

Remote HTTPS pages require a trusted WSS connection. Read the bridge setup before connecting. Use a trusted network and configure the allowed console origin.

Interpret the spectrum

The display shows measured subcarrier amplitudes and a motion score. The detector compares channel changes with a quiet baseline. Received power is shown in dBm, while the packet rate reports how much CSI input is arriving.

A single link cannot reliably determine how many people are present, where they stand or what the room looks like. Interference, placement and environmental changes can affect the signal. Establish a quiet baseline and validate the response with known movements in the actual room.

Review motion events

Motion events appear in the observation log with their source. Filter by Wi-Fi to review them, or export the session log as JSON. Optional audio cues acknowledge an event; they are designed interface sounds and do not represent captured audio from the room.
