Phone Room Scanning with WebXR Depth

Fathom can accumulate a point cloud from phone depth frames and tracked camera poses. This path requires a phone and browser that support WebXR depth sensing.

Open Fathom

In this guide

  1. Check compatibility
  2. Start a local development session
  3. Capture the room
  4. Understand depth limits

Check compatibility

Use a compatible Android phone with ARCore depth support and a browser that exposes the required WebXR depth API. The page must run over HTTPS. A camera permission alone does not provide depth sensing, and availability varies by device and browser.

The console checks for an immersive AR session. Actual depth access is requested when the session starts, so an AR-capable device can still fail to provide the required depth stream. Read the returned error if the scan cannot start.

Start a local development session

From the console directory, run bun run dev:phone and open the printed network address on the phone. The development server uses HTTPS and can proxy the local bridge under /bridge. Configure a certificate trusted by your device for a reliable setup.

For a desktop view, connect through the bridge and enable the option to send the scan to it. Both clients must reach the same bridge. See the hardware and connection guide for endpoint requirements.

Capture the room

Choose Scan this room and allow the requested AR camera access. Move slowly while sweeping across the floor, walls and furniture. The scanner combines depth measurements with the tracked phone pose and keeps accumulated points.

Finish scan ends the AR session. Inspect the captured cloud using the console views. The spatial recording controls and observation log serve different purposes: the cloud contains geometry, while the log contains session events.

Understand depth limits

On most supported phones, ARCore depth is estimated. Reflective, transparent or low-texture surfaces can produce sparse or inaccurate measurements. Fast motion, tracking drift and poor lighting can also degrade the reconstruction.

A phone scan is not equivalent to a calibrated surveying LiDAR. The project has automated protocol and geometry tests, but physical phone validation remains outstanding. Compare a scan against known dimensions before using it for measurements.
